# Phase 12 — accounts, results, ratings, matchmaking

Implemented as a self-hosted Node service backed by SQLite and the actual C# simulation worker. The Unity client uses account sessions, private rooms, casual/ranked queues, its filtered authoritative observation, and server-owned results. No external account, paid SDK, cloud deployment, or npm dependency was introduced.

## Delivered behavior

- Registration/login use per-account salted asynchronous scrypt; opaque random bearer tokens are stored as hashes, expire after twelve hours, and can be revoked. The database persists profiles, session hashes, match history, and per-queue ratings.
- Two distinct accounts join private 1v1 rooms and both ready before a World starts. Casual/ranked matchmaking partitions by victory mode and queue and widens its hidden-MMR tolerance with waiting time.
- Commands bind to authenticated account membership, require matching content/protocol and a monotonic sequence, and pass through the authoritative World's existing ownership, fog, cost, and gameplay checks. A repeated sequence is rejected, including after a rejected command. Each seat retains its latest 2048 valid request IDs across re-login; repeating one with a new sequence consumes that sequence but rejects the action before reaching the worker. Invalid or oversized IDs are not retained. Clients cannot submit a ranked result.
- A terminal worker event commits match status, both participants' history/statistics, and rating changes in one transaction. Duplicate results are ignored. Private matches record history without modifying ratings.
- Hidden Elo and visible ranked points are separate persisted values. Elo starts at 1000, uses K=32, and is independently keyed by queue/mode. Ranked visible points use +25/−15 with a zero floor and configurable Bronze through Legend bands. Profile/history responses omit hidden Elo.
- Local development binds loopback HTTP. Listening externally requires configured TLS certificate/key; no certificate checks are disabled. Version/content mismatches fail before account/gameplay processing. Body, request, authentication, command, room, queue, and worker-pending-request limits are bounded.
- Re-login restores an active seat/cursor. Disconnect grace, AFK, surrender, both-absent abort, worker failure, and interrupted-service restart are covered. Aborted matches never award ratings.

## Evidence recorded during implementation

The final Node run passed **16/16, zero skips, in 3.8854016 seconds**, using Node 22.12.0 with `--experimental-sqlite` and the installed .NET 8 runtime. Thirteen service tests use real HTTP/SQLite/crypto and an explicitly fake authority for deterministic failure/clock cases; three tests launch the compiled real C# World through its private stdin/stdout bridge. The exact output is preserved in [phase13-server-tests.txt](../testing/evidence/phase13-server-tests.txt).

The real-authority tests verified two distinct account seats, reciprocal fog filtering and local-player normalization; forged enemy ownership, hidden attack, replay, and public result submission rejection; accepted movement, paid Tender training, paid Storeyard construction, and gathering; rejected unaffordable/busy research; server-issued surrender with own statistics/history; ranked Dominion matching; re-login with restored seat/sequence; and a single authoritative hidden-MMR/visible-point award. A paid training regression additionally logs out and back in, repeats its request ID under the next sequence, verifies one queued Tender and a single 50-food charge, then submits a fresh ID at the following sequence and verifies the intentional second charge/queued unit.

Packaged integration also passed with **two actual Windows clients at both 1280-pixel and 1440-pixel viewport widths**, all using final build GUID **cdf8183365404135975644fd3c935a58**. The driver kills a guest client process, observes its disconnect, starts it again, and verifies re-login to the same match, authoritative completion/history and own statistics. These runs exercise the shipped Unity UI/client and local service, while the real-authority tests above verify that snapshots omit hidden enemy state. Detailed results are preserved in [phase13-online-1280.json](../testing/evidence/phase13-online-1280.json), [phase13-online-1440.json](../testing/evidence/phase13-online-1440.json), and the [final player matrix](../testing/evidence/phase13-player-matrix.md). This is automated two-client evidence, not a claim of human playtesting or external hosting.

The service suite verifies duplicate usernames, wrong passwords, hashed secrets/session revocation/expiry, mandatory version headers, private lobby readiness/access, sequence consumption, result idempotence and statistics filtering, queue partitioning/window expansion, disconnect and AFK outcomes, both-absent abort, authority failure, capacity/body/rate limits, database persistence with interrupted matches aborted, and exclusive database ownership preventing a second service startup from aborting the first process's live match.

## Practical limits

This is a runnable single-process alpha backend, not an already deployed public service. Physical device, two-human latency/comfort/fun, live competitive balance, certificate/host provisioning, backups/operations, e-mail recovery, public abuse moderation, and scale testing remain operator/product acceptance work. Active client reconnect is implemented; restarting the authority aborts active Worlds and preserves completed history without issuing fabricated results. Retained finished rooms occupy the 16-room alpha capacity until dismissal or ten-minute expiry. No placements, seasons, extra modes, or multi-region service is claimed.
